2. Core gameplay state machine

GameManager should be the central authority.
use an enum rather than scattering booleans throughout the project:
Then expose state changes through an event:
That lets the camera, UI, audio, dialogue and player controller react without becoming tightly coupled.
The player should be composed rather than having one enormous controller.
The important thing is to make the controller physics-oriented rather than animation-oriented.
The desired velocity can be conceptually modeled
Your ~200 km/h terminal velocity becomes the cap rather than a fixed movement speed.
make the terminal velocity angle-dependent:
Start game → enter aircraft → door opens → jump → control body → reach formation → receive lock confirmation → deploy parachute → steer canopy → land on target → receive score.
